# ADR-0005: единый слой запросов к графу

- Статус: предложено
- Дата: 2026-09-23

## Контекст

Пайплайн использует NetworkX, а сервер строит `GraphIndex` из `graph.json`. Сейчас BFS,
хронологические пути, upstream и timeline частично реализованы повторно. Из-за разных контейнеров
могут расходиться порядок tie-break, трактовка дат и результат одного и того же вопроса.

## Решение

Ввести минимальный read-only протокол графа и два адаптера: `NetworkXGraphView` для пайплайна и
`JsonGraphView` для опубликованного payload. Алгоритмы `chrono_reach`, `money_path`,
`common_receivers`, `upstream`, `edge_timeline` разместить в `gm/graph/queries.py` и тестировать
одним набором тестов на обоих адаптерах.

Миграция выполняется по одной функции. Старую и новую реализацию сначала запускают параллельно на
synthetic и выборке real graph; старая удаляется только после равенства нормализованных результатов.

## Последствия

- Пайплайн и сервисы получают одну семантику обходов без зависимости сервера от NetworkX.
- Протокол должен сохранять порядок рёбер входного payload, иначе изменятся tie-break и тексты.
- `GraphIndex` временно остаётся совместимым фасадом; приватные `_need`/`_gids` заменяются
  публичными методами после миграции клиентов.
