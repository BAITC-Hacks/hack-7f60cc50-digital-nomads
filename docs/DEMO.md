# Демо «Граф денег» — сценарий на 5 минут

Цель демо: за пять минут доказать не количество экранов, а ответ на вопрос аналитика: **кого смотреть первым и почему**.

## Подготовка

```bash
python -m pip install -r requirements-lock.txt
python run.py --data data --out out
python serve.py --out out
```

Открыть `http://localhost:8765`. Держать рядом терминал с командами `explain.py`.

Показать обзор: 2 248 узлов, 3 119 рёбер, 45 кластеров, топ-5.

## 4:30–5:00 — AI и финал

> Ассистент не придумывает роли и суммы. Он вызывает ограниченные функции графа, а каждый gid в ответе проверяется по фактам. Без API-ключа работает детерминированный режим.

Финальная фраза:

> Вместо ручного просмотра 2 248 клиентов аналитик получает топ-30, объяснение каждого места, схему потоков и готовый пакет для углублённой проверки.

## Каверзные вопросы жюри

**Почему вашим ролям можно доверять без ground truth?**  
Мы не заявляем accuracy. Для каждой роли есть проверяемое правило; `explain.py` показывает факты против порогов. На синтетике есть end-to-end тест, а для модели границы — CV, калибровка и режим отказа.

**Почему 409 конечных получателей — не ошибка четвёртого колена?**  
368 наблюдаются на коленах 1–3, 21 удерживают не менее 80% крупного входа, и только 20 являются оценёнными на четвёртом колене. У последних сниженный score и явная оговорка.

**354 клиента отдали больше, чем получили. Это ошибка?**  
Нет. Граф содержит только исходящие пути от seed, поэтому часть внешних входов не видна. Это отражено типологией `external_funding`; полный баланс клиента не утверждается.

**Почему не GNN?**  
Нет разметки, граф мал, а ТЗ запрещает чёрный ящик. Формальные правила легче защищать и воспроизводить в AML-процессе.

**LLM может обвинить клиента или выдумать gid?**  
Роли и приоритеты считаются без LLM. Ответ ассистента проходит проверку gid; неподтверждённые значения помечаются, выводы сформулированы как гипотезы.
